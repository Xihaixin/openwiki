# 上下文策略参考

本文档定义精准修改时如何以最小上下文代价获取足够信息。所有数值参数可按项目规模调整,但层级纪律不得放宽。

## 一、L0 锚点采集

### 锚点的合法形式

- `文件路径:行号`(最优)
- 文件路径 + 函数名/类名/变量名
- 错误信息堆栈中的位置

### 用户未提供锚点时

不猜测、不盲读。按以下顺序获取锚点:

1. 直接向用户索取具体位置。**这是首选**,因为用户通常已知问题所在。
2. 若用户只能描述现象,用 `search_content` 以精确符号定位:
   - 函数定义:`def\s+函数名` 或 `async def\s+函数名`
   - 类定义:`class\s+类名`
   - 常量或配置项:直接匹配标识符
   - 错误字符串:用原文片段做字面匹配(注意正则转义)
3. 先用 `files_with_matches` 模式确认命中范围;命中过多时收紧关键词或加上边界。

### 锚点清单

取得锚点后维护一份清单:主锚点(必须修改处)+ 关联锚点(可能需要同步处)。关联锚点来自用户指定与 L2 的搜索结果,不得凭印象添加。

## 二、L1 定点读取

### 窗口计算

`read_file` 的 `offset` 为起始行(1 起算),`limit` 为读取行数。

| 场景 | offset | limit |
|---|---|---|
| 单行或局部小改 | `max(1, 行号 - 50)` | `100` |
| 需理解跨函数调用链 | `max(1, 行号 - 100)` | `200` |
| 文件总行数 < 200 | 省略 | 省略(整读更省事) |

### 边界处理

- 锚点靠近文件开头时,offset 取 1,不取负数。
- 一次读取不足以理解时,**先补充读取相邻窗口**,而不是直接改为全文读取。
- 记录已读取的区间,避免重复读取同一区间。

## 三、L2 关联扩散

关联扩散的目标是「找到关联代码」,而非「读完关联代码」。

### 第一步:收敛

```
search_content(
  pattern     = 精确符号(需正则转义),
  outputMode  = "files_with_matches"
)
```

此步只回答「哪些文件提到它」,不读取内容。

### 第二步:分组

命中文件超过 5 个时,按目录或模块分组,优先展开与主锚点同属一个模块的那一组。其余分组若与本次修改确实相关,再逐个展开。

### 第三步:小窗口读取

```
search_content(
  pattern       = 同一符号,
  outputMode    = "content",
  contextAround = 15      # 一般场景
  contextAround = 30      # 需要看清完整函数体时
)
```

只用 `contextAround` 查看命中处周边,**不因此整文件读取**。

### 收敛判据

满足任一即可停止扩散:

- 已确认所有修改点及其直接调用方
- 命中集合不再增长
- 命中已扩散到与本次问题明显无关的模块

## 四、L3 全文读取

仅在满足以下条件之一时执行,且须向用户说明理由:

- 同一文件在 L2 中被命中 3 次以上
- 修改面确实覆盖整个文件(调整文件级结构、重命名文件内公共符号等)
- 文件行数小于 200

## 五、工具选择矩阵

| 目的 | 工具 | 关键参数 |
|---|---|---|
| 已知路径看局部 | `read_file` | `offset` + `limit` |
| 定位符号定义或引用 | `search_content` | 精确正则并转义,如 `def\s+foo`、`Foo\(` |
| 查看命中处上下文 | `search_content` | `outputMode: "content"` + `contextAround` |
| 按名称模式找文件 | `search_file` | `pattern` + `recursive` |
| 查看目录结构 | `list_dir` | `ignore_globs` 排除噪声目录 |
| 统计某符号出现次数 | `search_content` | `outputMode: "count"` |

## 六、搜索前置检查

执行全局搜索前,确认项目的 `.gitignore` 已覆盖构建产物与缓存目录。若已覆盖,基于 ripgrep 的 `search_content` 会自动遵守,无需额外过滤参数。若搜索结果中出现大量 `*.pyc`、`node_modules`、`.next` 等噪声,说明忽略规则未生效,此时改用 `glob` 或 `ignore_globs` 参数显式过滤。

## 七、反模式

以下行为视为违反本策略:

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 拿到任务先遍历整个项目目录 | 消耗大量上下文却无有效信息 | 从用户给的锚点出发 |
| 用宽泛关键词全局搜索 | 命中数百处,无法收敛 | 用带边界的精确正则 |
| 命中文件后直接全文读取 | 单个大文件即撑满上下文 | 先 `contextAround` 小窗口 |
| 为保险起见多读几个文件 | 上下文线性膨胀 | 需要时再读,读完即用 |
| 发现旁路问题顺手一起改 | 超出授权范围,引入回归风险 | 报告给用户,由用户决定 |
