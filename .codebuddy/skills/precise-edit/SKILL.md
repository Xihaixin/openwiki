# Precise Edit —— 精准修改工作流

## 核心立场

本 Skill 服务于「已知问题位置的小范围修改」,不服务于开放式重构。每一次代码读取都必须先有明确目的;没有目的的读取即视为上下文浪费。宁可多问一句锚点,不可多读一个文件。

## 第一章 启动协议

激活本 Skill 后,在执行任何代码读取之前,先完成上下文挂载。

### 1.1 挂载项目专属上下文

探测项目根目录下的 `.codebuddy/project/` 目录:

- **存在** → 读取 `PROJECT.md` 与 `LESSONS.md` 全文(二者为常载项);`ARCHITECTURE.md` 与 `CONVENTIONS.md` 仅在与当前任务相关时按需加载。
- **不存在** → 执行 `scripts/init_project_context.py` 生成脚手架,并告知用户:项目上下文目录已初始化,补充项目特有约定后可获得更准确的修改结果。若用户拒绝初始化,则跳过挂载继续任务,但须明确提示「本次修改未加载项目专属约定」。

### 1.2 挂载任务定义

探测 `.aidocs/task/` 目录:

- 存在且与当前任务匹配的任务文档 → 读取该文档作为任务上下文。
- 不存在或无匹配项 → 跳过,不报错。

### 1.3 降级规则

`.aidocs/` 目录在部分环境中可能缺失(该目录常被 `.gitignore` 忽略,团队 clone 后不存在)。探测失败时静默跳过,不得中断任务,不得向用户报错。所有对 `.aidocs` 的写入操作,执行前须先确认目录存在,不存在则创建。

### 1.4 输出挂载报告

完成挂载后,三行以内简述:已加载哪些项目上下文、未找到哪些、本次任务是否有任务定义。若用户未提供问题锚点,在此阶段向用户索取。

## 第二章 精准定位协议

完整的层级参数与工具选择矩阵见 `references/context-strategy.md`。正文只保留必须遵守的纪律。

### 2.1 层级纪律

严格按 L0 → L1 → L2 → L3 顺序推进,不得跳级:

| 层级 | 目的 | 手段 |
|---|---|---|
| L0 锚点采集 | 确定修改的确切位置 | 从用户处取得 文件路径 + 行号/函数名/类名;用户未给出时,用精确符号搜索定位 |
| L1 定点读取 | 理解锚点局部 | `read_file` 带 `offset`/`limit`,窗口 ±50 或 ±100 |
| L2 关联扩散 | 定位关联代码 | 先用 `search_content` 的 `files_with_matches` 收敛文件集,再对命中处用小窗口读取 |
| L3 全文读取 | 必要时才整文件读 | `read_file` 不带 offset,须满足触发条件并向用户说明理由 |

### 2.2 硬约束

- 禁止在未取得锚点的情况下,对目录执行整目录或整项目的探索性读取。
- 禁止「为避免遗漏,先把相关文件都读一遍」的预防性读取。
- 禁止对 `search_content` 的命中文件直接全文读取——必须先收敛、后小窗口读取。
- 单次任务累计读取文件数超过 8 个时,向用户说明原因并确认后再继续。
- 修改范围严格限定在用户指定的问题及其必要关联处;发现其他问题时报告给用户,由用户决定是否处理,不得顺手扩大改动。

### 2.3 收尾核对

修改完成后,核对改动是否超出用户授权范围,并列出实际修改的文件清单。

## 第三章 复盘协议

### 3.1 触发条件

**仅在用户明确说出「复盘」「沉淀」「总结」等指令时触发。** 不得自行判断任务结束而主动复盘,不得在任务进行中插入复盘环节。

### 3.2 执行流程

1. 获取当前日期,确定归档路径(年/月两层)。
2. 回顾本次任务全过程,提取:用户指出的错误、AI 自身判断失误、返工点、反复修正之处。
3. 在 `.aidocs/openwiki/<YYYY>/<MM>/` 下生成任务过程性总结文档。
4. 判断哪些教训属于**长期有效的技术约定**;是则追加到 `.codebuddy/project/LESSONS.md`。
5. 追加前必须全文检索 `LESSONS.md`,存在同类条目时合并更新,不得重复新增。

### 3.3 写入规范

条目格式、去重合并与防膨胀规则见 `references/lessons-format.md`。

### 3.4 禁区

**`.aidocs/archive/` 由用户手动维护,AI 严禁写入、修改或删除其中任何内容。**
